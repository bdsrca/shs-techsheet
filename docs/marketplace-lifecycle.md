# Marketplace Lifecycle

A student marketplace has one main loop: browse, post, message, meet, resolve.

## 1. Browse

Browsing should be public. Students should not need an account just to see whether the marketplace has useful listings.

Good browse behavior:

- search appears early
- category entry is easy
- cards stay dense enough for scanning
- filters are reflected in the URL
- pagination is server-driven
- map mode is optional, not required

## 2. Post

Posting should ask for the useful basics, not a life story:

- title
- price
- category
- condition
- broad meetup area
- short description
- photos

The product should avoid exact home addresses, class schedules, phone numbers, and personal email addresses inside public listing content.

## 3. Message

The buyer starts with an inquiry. If the listing is available and contactable, the inquiry becomes a thread. The thread is scoped to the listing and the two users.

## 4. Meet

The product should keep the meetup rule simple:

- public place
- daytime when possible
- bring backup if needed
- check the item before paying
- walk away if something feels wrong

## 5. Resolve

After a deal, the seller can mark the listing as sold. A buyer can leave a seller rating when eligible. Reports and moderation logs remain available for review.
